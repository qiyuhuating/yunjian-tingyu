## 问题复现、根因与最小修复

| 问题 | 修复前证据与根因 | 当前行为与回归 |
| --- | --- | --- |
| 截断媒体被标成成功 | Gemini `MAX_TOKENS` 归一成 `length`，前端仅提示后仍保存媒体 | 截断、断流、空内容、未完成结束均失败；保留原输入与失败反馈，不保存成功媒体 |
| PCM 被拆成多条不完整语音 | 每个 PCM 流块独立包装 WAV，三块又触发两文件限制 | 有界收集、结束后合并 PCM，生成一个完整 WAV；校验总长度、原始字节和数量 |
| 无效文件伪造成功图片或语音 | 非空 base64 和服务 MIME 被当成充分证据，`abcd` 字节可保存为图片 | 对生成文件实际解码；校验 PNG 结束块、WAV/WebP 容器长度及消息 MIME；无效文件显示未发送 |
| 异步保存清空后来输入 | 保存后无条件清空日记、纸条、动态和角色草稿 | 清理仅针对提交快照；共享草稿校验保护重进页面的新实例，重复点击不产生相同提交 |
| 刷新保护存在空隙 | 清除草稿防抖计时器后先等待队列，尚未标记待写入，立即刷新绕过保护 | 同步加入保存队列；立即刷新触发离开保护，落盘后刷新恢复原输入 |
| 去重附件引用悬空 | 已上传但未提交的相同原件可被旧引用删除触发的 GC 销毁 | 取消自动破坏性附件清理；保留内容去重、原件、事务和冲突校验，新引用仍可读取完整字节 |
| 免费模型可选参数不兼容 | 统一采样配置不能代表每个免费路由的实际能力；Liquid 免费端点实际拒绝元数据声称支持的 `top_p` | 元数据过滤、未知免费路由默认采样；按真实 400 错误增加 Liquid 精确能力例外，不盲目重试 |
| 角色姓名前缀不断复制 | 应用把自己的助手历史也加上发送者标签，模型继续复述，单轮最多重复 11 次 | 助手自己的历史不追加姓名；其他成员来源标签保留；文字与 Realtime 上下文均覆盖。原始数据库消息不改写，16 卡重跑前缀计数均为零 |

OpenRouter 策略依据[官方模型元数据](https://openrouter.ai/docs/guides/overview/models)和[官方提供商路由说明](https://openrouter.ai/docs/guides/routing/provider-selection)。只有实际发送且要求支持的惩罚或推理字段才启用对应路由要求。能力缓存只存在于运行时；数值模型上限、状态 Schema 和数据库版本仍与原 v3 草稿兼容，不把新元数据写入旧严格 Schema。

附件处理选择数据安全优先：未引用原件继续保留，空间占用可能增加；当前备份导出状态中引用的附件，**不包含所有孤立、未引用原件**。不能把它称为整个 IndexedDB 资产库的完整归档。后续 P2 应先建立可核对的资产归档与引用关系，再讨论回收。失败恢复产生的全新 UUID 附件仍可明确回滚清理，未恢复自动 GC。

## 真实 API 与 Android 门槛

可选真实测试：`node outputs/mori-phone/scripts/live-p0.mjs`。从进程环境读取 `OPENROUTER_API_KEY`、`DEEPSEEK_API_KEY` 和相应 `_MODEL`，执行首轮、复用及三角色并发协议探针与无效 Key 负例；不自动重试失败请求，不使用付费 OpenRouter 回退。默认探针输出上限 128；本次保留 128 截断的失败记录，明确提高 Liquid 单次输出上限到 1024 后重跑，不能把失败改为成功。模型元数据错误也有原始失败与诊断报告。

官方 DeepSeek 五次协议请求和无效 Key 401 均符合预期。Liquid 五次完整流式回复中四次通过严格角色标记、一处标记不符；两次 128 上限请求真实结束为 length、无内容，均失败。poolside 免费路由 429；nvidia 免费路由超时未获 usage；持续对话的 Liquid 免费路由同样多次 429，不能报告免费模型整套验收通过。

累积已返回 usage：**6,439,196 Token**；保守预留上界 **30,603,560**，低于用户最终授权 100,000,000 上限。缺 usage 的错误或超时不按零消耗认定，也不冒充实际账单。输入 Token 加权缓存率：DeepSeek **84.19%**（995 次），OpenRouter **36.74%**（26 次可测、16 次缺缓存 usage）。仅修复后的 DeepSeek 角色对话：**87.25%**，自动评审单列 **12.12%**，不把不同工作负载的比例作算术平均。

16 张卡分别保留每个原件 SHA-256，所有卡均用实际导入器进入三个隔离测试设备。峰值六路网络请求（初次双 Provider），修复后三路。它是独立角色/设备并发，不能冒充同一应用内 Hermes 任务调度、12 人交接或 Android 帧率。修复后 384 轮 UI 对话全部保存，16 次冷召回同时命中更正的热水、周末计划和独有记号。合并测试备份再次经源码备份/恢复器写入独立 IndexedDB：812 条消息、135 条记忆、12 份去重原件，消息 ID、原文、角色设定、记忆来源与修订一致。

盲标签自动评审 16 次，15 次引用校验通过，15 次均偏好修复后；评审模型将“我是清主人”误判为漂移，这项结论明确撤销。修复后同卡 v2 的“我是你朋友，一个会记事的聊天对象”有身份弱化，保留缺陷。引用存在不代表评审推理正确；24 轮不能证明长期人格永不漂移，未对露骨成人内容作质量验收。

详见 `docs/p0-live-aggregate-results.json` 与 `docs/角色持续对话验收-2026-10-08.md`。私人原卡、完整对话、自动评审原文和测试备份仅保存在本地交付目录，不进入应用仓库。报告无 Key、鉴权头；CI 不注入账号 Key，保留无凭据的本地 fixtures 路径。

本机没有已连接 adb 设备，未找到 Android SDK，也没有提供原签名私钥。既有提交 CI 的成功只作为历史证据。新增提交必须由完整检出的 CI 独立复核仓库 SHA-256、既有 APK CRC、随包 Via/资源逐字节一致与 Android 35 Java 编译；其结果以对应提交的 Actions 记录为准。原 APK、Via 和历史源码 ZIP 保留原件，未把它们描述成本次新版。

## 提交与恢复纪律

原稳定 main 与草稿起始提交完整保留。Git 回退用于源码对照，不是数据库回滚策略；尤其不能把回退旧 APK 当作 v3 数据恢复。升级设备之前应验证可用备份，再进行覆盖安装和恢复测试。此阶段不合并、不发布、不改签名、不外置或删除 Via。

下一阶段只有在 P0 剩余真实 API 门槛完成后，才将草稿作为稳定开发基线并开始 P1 任务状态机。失败报告与本轮成功报告的范围明确区分；CI 通过也不能替代正式 APK 发布验收。
