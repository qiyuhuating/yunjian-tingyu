# 云笺听雨：回合回执、文件工作区与受限 Agent 协作（2026-10-10）

## 基线与依赖
本分支依赖 PR #19（又依赖 #18、#12），不修改已有发布包。保持界面字体、Via、既有密钥和 IndexedDB 版本 3 不变。新增状态字段采用 Zod 默认值，旧记录/旧备份在读取时补齐。

## 已实施的事务性执行回执
- `turnReceipts` 随 PhoneState 和聊天消息一起经 `writeLocal` 的 IndexedDB 事务保存，关联 userId/thread/模型回合/发言人名单/已提交角色/请求阶段/请求次数。
- 发送外部 POST **之前**，先原子写入 `in_flight`。遇到断电/应用被杀，只能确定“可能已发送且计费”，不能擅自重发。
- 模型响应解析成功后，同一 `commit` 写入角色消息、角色关系变化、发言人已完成回执。群聊后继成员的完成游标不再只是 React ref。
- 重新加载时只允许继续尚未完成的角色；状态为 `in_flight/needs_review` 的回合必须由用户明确确认再次可能计费，旧记录不得自动重复。
- 旧记录没有回执时保留原行为；已完成回合不能重新启动。

## 文件处理边界
- `agent-workspace.ts`：按 thread 隔离、有界大小、无目录穿越的本地文本工作区。读/写/列出是实际可调用的确定性工具。写入要求调用方具备明确许可和 `expectedRevision` 乐观锁，不具备任意设备磁盘权限。
- 文件附件仍先保存原始 Blob，已有解析器能抽出的文字才会进入 `imports/{消息ID}/{文件名}`，并标注“文字已加入工作区”。解析失败或空间不足不得谎称文件已被理解。
- 工作区文字默认最多每文件 18000 字符，全部工作区最多约 1MB、150 文件。压缩包/PDF/大型文件解析限制保持现状；没有无限上下文或真实执行项目代码的能力。

## 真实多 Agent 协作的最小闭环
- 用户在群聊中打开**已成功索引的附件**消息操作，主动选择“协作审阅文件”；调用前二次确认文件将发往最多四位群成员各自选定的模型，可能分别计费。
- `agent-orchestrator.ts` 根据已保存的工作区文字依次请求不同角色，后继角色收到前一位的审阅摘要，结果按角色保存为 `reviews/{任务ID}/{角色ID}.md`，同时写入群聊天记录。
- `agentJobs` 记录阶段、完成角色与中断。只允许未开始的任务运行，不会从异常退出自动重放可能计费的步骤。
- 工具范围暂为本地文本列出/读取/版本化写入。**没有 Shell、任意文件系统、软件构建、自动测试或自动修改原源码权限**，AI 不得声称做过这些操作。
- 角色独立供应商配置沿用现有角色连接，不共享自定义地址密钥。

## 角色记忆可靠性
- 自动长期记忆携带来源消息 ID、时间与逐字证据；每次召回前再次核对原话未被删除、编辑或标记失败。证据不再成立则不进入角色 prompt；人工锁定记忆和旧版无来源记录仍保留，避免误删用户资料。
- 自动整理逻辑对旧结果、来源修改和跨角色隔离的原有校验不变。

## 不虚报的验收边界
- 本工作只证明受限文件阅读、角色间顺序审阅、持久化状态和权限控制在代码层面可用；真实模型对文件理解的质量需单独测试。
- 目前尚未实现多 Agent 并行 DAG、受限容器中的代码运行/编辑/自动测试、可复核的执行回执、跨设备同步、角色长期独立文件索引与全量虚拟化项目工作区。
- `PhoneState` 仍包含多个领域；本轮隔离了独立可测试的执行/工具模块，但**大型状态和 IndexedDB 服务尚未全面拆分**，不能宣称完成大型模块治理。
- GitHub Actions + Android 无签名候选构建均必须通过；真实 Android 实机和 API 端到端测试在 #15 完成前继续阻止正式发布。

## P1 增量：请求代次隔离、工作区原子预检和线程模块拆分
- 聊天回合每次 POST 前持久化递增 attempts，提交时核对相同代次；人工重试后返回的旧响应不得写入消息或重复增加关系值。
- 多角色文件审阅的每个回复也核对 attempts、当前发言人顺序、文件版本。旧模型请求迟到只能被拒绝，不会修改审阅报告。
- 工作区写入前完整计算预期状态的大小和版本，失败不再污染已有文件；只读工具返回对象副本，避免绕过工具写入许可。
- 将 IndexedDB 线程读取、增量写入和删除独立至 local-thread-store.ts，仍与其他状态在同一事务提交。数据库版本保持 3。
- 已扩充过期响应、权限隔离和超额写入回归测试。仍不声称具备真实服务商的精确计费保证，真实 Android 与完整 Agent 工具调度仍需进一步验证。
