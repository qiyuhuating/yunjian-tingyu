# 云笺听雨：回合回执、文件工作区与受限 Agent 协作（2026-10-10）

## 基线与依赖
本分支依赖 PR #19（又依赖 #18、#12），不修改已有发布包。保持界面字体、Via、既有密钥和 IndexedDB 版本 3 不变。新增状态字段采用 Zod 默认值，旧记录/旧备份在读取时补齐。

## 已实施的事务性执行回执
- `turnReceipts` 随 PhoneState 和聊天消息一起经 `writeLocal` 的 IndexedDB 事务保存，关联 userId/thread/模型回合/发言人名单/已提交角色/请求阶段/请求次数。
- 发送外部 POST **之前**，先原子写入 `in_flight`。遇到断电/应用被杀，只能确定“可能已发送且计费”，不能擅自重发。
- 模型响应解析成功后，同一 `commit` 写入角色消息、角色关系变化、发言人已完成回执。群聊后继成员的完成游标不再只是 React ref。
- 重新加载时只允许继续尚未完成的角色；状态为 `in_flight/needs_review` 的回合必须由用户明确确认再次可能计费，旧记录不得自动重复。
- 旧记录没有回执时保留原行为；已完成回合不能重新启动。

## 文件处理边界
- `agent-workspace.ts`：按 thread 隔离、有界大小、无目录穿越的本地文本工作区。读/写/列出是实际可调用的确定性工具。写入要求调用方具备明确许可和 `expectedRevision` 乐观锁，不具备任意设备磁盘权限。
- 文件附件仍先保存原始 Blob，已有解析器能抽出的文字才会进入 `imports/{消息ID}/{文件名}`，并标注“文字已加入工作区”。解析失败或空间不足不得谎称文件已被理解。
- 工作区文字默认最多每文件 18000 字符，全部工作区最多约 1MB、150 文件。压缩包/PDF/大型文件解析限制保持现状；没有无限上下文或真实执行项目代码的能力。

## 真实多 Agent 协作的最小闭环
- 用户在群聊中打开**已成功索引的附件**消息操作，主动选择“协作审阅文件”；调用前二次确认文件将发往最多四位群成员各自选定的模型，可能分别计费。
- `agent-orchestrator.ts` 根据已保存的工作区文字依次请求不同角色，后继角色收到前一位的审阅摘要，结果按角色保存为 `reviews/{任务ID}/{角色ID}.md`，同时写入群聊天记录。
- `agentJobs` 记录阶段、完成角色与中断。只允许未开始的任务运行，不会从异常退出自动重放可能计费的步骤。
- 工具范围暂为本地文本列出/读取/版本化写入。**没有 Shell、任意文件系统、软件构建、自动测试或自动修改原源码权限**，AI 不得声称做过这些操作。
- 角色独立供应商配置沿用现有角色连接，不共享自定义地址密钥。

## 角色记忆可靠性
- 自动长期记忆携带来源消息 ID、时间与逐字证据；每次召回前再次核对原话未被删除、编辑或标记失败。证据不再成立则不进入角色 prompt；人工锁定记忆和旧版无来源记录仍保留，避免误删用户资料。
- 自动整理逻辑对旧结果、来源修改和跨角色隔离的原有校验不变。

## 不虚报的验收边界
- 本工作只证明受限文件阅读、角色间顺序审阅、持久化状态和权限控制在代码层面可用；真实模型对文件理解的质量需单独测试。
- 目前尚未实现多 Agent 并行 DAG、受限容器中的代码运行/编辑/自动测试、可复核的执行回执、跨设备同步、角色长期独立文件索引与全量虚拟化项目工作区。
- `PhoneState` 仍包含多个领域；本轮隔离了独立可测试的执行/工具模块，但**大型状态和 IndexedDB 服务尚未全面拆分**，不能宣称完成大型模块治理。
- GitHub Actions + Android 无签名候选构建均必须通过；真实 Android 实机和 API 端到端测试在 #15 完成前继续阻止正式发布。

## P1 增量：请求代次隔离、工作区原子预检和线程模块拆分
- 聊天回合每次 POST 前持久化递增 attempts，提交时核对相同代次；人工重试后返回的旧响应不得写入消息或重复增加关系值。
- 多角色文件审阅的每个回复也核对 attempts、当前发言人顺序、文件版本。旧模型请求迟到只能被拒绝，不会修改审阅报告。
- 工作区写入前完整计算预期状态的大小和版本，失败不再污染已有文件；只读工具返回对象副本，避免绕过工具写入许可。
- 将 IndexedDB 线程读取、增量写入和删除独立至 local-thread-store.ts，仍与其他状态在同一事务提交。数据库版本保持 3。
- 已扩充过期响应、权限隔离和超额写入回归测试。仍不声称具备真实服务商的精确计费保证，真实 Android 与完整 Agent 工具调度仍需进一步验证。

- 失败回执也须匹配请求代次；旧请求延迟报错不会污染后续有效请求或留下错误的流式半成品。


## P2 草稿：三项底层约束（2026-10-10）

### 因果消息模型
- 每次普通或群聊请求携带源用户消息 ID，在发送模型请求前构造截至该消息的历史快照；后发的排队消息不会进入较早回合的上下文或改变群成员路由。
- 同一回合其他角色已保存的回复使用 `turnId` 关联，作为显式标记的参考证据，而不伪装成第二次用户请求；修改原始消息会拒绝生成。
- OpenAI 必须收到供应商真实 `[DONE]`；Anthropic 必须收到 `message_stop`；Gemini 仅接受合法终止原因后结束。不得因网络 EOF 伪造成功。

### 持久化执行模型
- 文字回复和媒体指令的入队回执在同一个本机事务中提交。媒体执行记录包含来源用户、角色、任务 ID、请求代次和状态。
- 在实际生成/交付媒体前提交 `in_flight`；确认消息持久化时在同一事务将任务提交为 `completed` 并关联输出 ID。异常进入 `needs_review`，旧请求不得覆盖新代次。
- 用户能在聊天菜单恢复未完成的媒体任务；存在可能重复计费的情况必须确认。不能承诺服务商侧绝对仅计费一次。原生媒体二进制的恢复仍需进一步补齐资源级回执。

### 可信结果模型
- Agent 审阅报告同时保存源文件 ID/版本、角色与请求代次、报告工作区文件 ID/版本、聊天消息 ID；核验结果时检查这些记录是否对应并且内容一致。
- 删除或修改来源、替换报告、修改对应聊天消息后，报告核验失效，不能继续把它作为已核实的 Agent 交接材料。
- 阶段摘要保留实际使用的原消息 ID、原文片段、发送者和时间；进入模型上下文前再次核对。旧版缺少来源的摘要保留但不自动引入提示词。
- `reportEvidence` 核验的是**内容与来源的一致性，不是代码已运行、不代表模型审阅正确**。仍没有通用 Shell 执行器、自动验证多文件成果或任务级费用硬上限。

### 发布控制
本分支依赖 PR #21，独立保留为草稿；CI、Android 无签名候选构建、真实 API/网络和目标 Android 实机验收未全部通过时禁止合入主分支或发布稳定 APK。


## P3：崩溃恢复与证据完整性加固（PR #24，独立草稿）

**参考及复用边界：**
- [LangGraph persistence](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint/README.md)：借鉴“线程级检查点 + pending writes + 不重复执行已完成步骤”的分离原则；没有移植其 Python/服务端运行时。
- [Pydantic AI durable execution](https://github.com/pydantic/pydantic-ai/blob/main/docs/durable_execution/overview.md)：借鉴逐步保存模型调用/工具副作用和人工续接原则；没有直接复制 Python 代码。
- [@noble/hashes](https://github.com/paulmillr/noble-hashes)：**直接复用已锁定在本项目依赖中的 SHA-256**，不重复维护本地加密算法。
- [SillyTavern](https://github.com/SillyTavern/SillyTavern)：继续参考角色扮演设计与世界书激活语义。其主仓库使用 AGPL-3.0；本轮不将源代码直接拷贝入项目，以免制造许可证义务不明的衍生代码。

**实现契约：**
1. `queuedTurns` 持久化用户发送意图、回合模式及其来源消息，和消息本身同事务提交。启动后从持久化待处理记录恢复；只有源消息完全匹配、`turnReceipts` 不存在或明确处于 `queued`，才允许自动发送。回执已进入 `in_flight` 或 `needs_review` 不可自动重发。
2. 发送前在同一事务将回执转成 `in_flight` 并移除待处理项；群聊上一角色已持久化而下一角色尚未发送时，恢复下一角色的 `queued` 任务。用户删除、编辑源消息必须阻止旧任务。
3. 阶段摘要写入 `sourceDigest`，对 `through` 之前有效消息的 ID、角色、发言人、文本及附件引用形成完整 SHA-256 摘要。滚动摘要再生成前仍核对旧摘要，历史消息发生变化时失效并重建。没有完整哈希证据的旧摘要不会自动进入模型提示词；旧内容仍保留在备份数据内。
4. 自动记忆有多个来源 ID 时必须**全部**仍有效；单条来源失效，不得借另一条仍在的来源进行错误召回。
5. Agent 任务保存原文件 SHA-256，报告保存输出 SHA-256；即使版本号未更新，同内容篡改也会失效。哈希确保一致性，不证明模型分析正确或已执行测试；本机整个数据库被有权限的恶意程序替换仍不具有不可抵赖性。
6. 模型返回的原生媒体先写入本机 Blob 存储，再与文本消息、媒体消息、回合回执同事务完成；文件保存失败改为随正文同时写入持久化通知。不再把已提交成功的文字回复依赖于进程内 `File[]` 的后续上传。
7. 恢复备份时只暂存被目标状态引用的附件；恢复提交失败，核对最后成功持久化状态后，回收新增且确定无人引用的暂存附件，绝不删除已有状态仍引用的资产。

**明确剩余限制：** 该分支不是一个通用 Agent 执行环境。仍需追加任务预算、可授权的真实测试执行工具、完整输入配置快照、查询索引、分域状态提交、Android 实机连接与签名验收。本次不改动包名、UI 字体、Via 或已发布 APK。
