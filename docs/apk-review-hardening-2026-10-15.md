# Android 补丁审核与 Via Agent 整合

审核与验证完成日期：2026-10-16。输入为 `0001-fix-android-harden-network-trust-SSRF-gua.patch`，固定基线 `f6c597c`。补丁 SHA256：`11a18e95861ea9a082352c8f46af0c284ff21ccd215ad7edc0592635b76656cc`。补丁文字、作者说明和其中自述的测试不作为已执行证据。

用户最终范围：保留既有 Via 集成，关闭定位；保持 HTTP 链接、APK 安装和浏览器通常应有的功能；Agent 能读取、点击、填表和下载网页内容。

## 审核结论

原补丁不宜整包采纳，选择性合入。代码质量与需求符合性两个独立审核均指出导出迁移、代理判断问题；需求审核另指出全应用网络策略和 Via 权限改动超出范围。

| 改动 | 结论与依据 |
|---|---|
| 全应用只允许 HTTPS、只信任系统 CA | 不合入。会阻断 Via 的普通 HTTP 网页及部分代理证书场景；保留原 Via 网络配置。本地 API 桥仍执行原有 HTTPS、域名和地址约束 |
| 移除 Via 安装、凭据、快捷方式、启动器及广播权限 | 不合入。只在既有权限过滤中新增删除精确、粗略和后台定位权限；其余保留原合包行为 |
| 收窄 Via FileProvider 目录 | 不合入。用户自选下载目录在白名单之外时无法打开/分享文件；保留原共享规则及必要 authority 等宽迁移 |
| DNS 重绑定守卫、AddressPolicy 拆分 | 暂缓。候选代理列表中有任一代理就关闭守卫，不能证明实际连接使用代理；直连回退可能仍绕过保护。没有把不完整安全修复当成已封堵 |
| 导出迁移到 filesDir、复用输出流、2GB上限 | 暂缓整组。旧 cache 下载文件未搬迁，新日志却按新根目录查 basename 并删除旧日志，第二次启动失去恢复入口。保留既有导出和日志实现 |
| 固定延迟5秒暂停 WebView、onStop再次保存 | 暂缓。延迟不是保存完成的确认，需单独验证后台生命周期；保留既有 NativeFlush |
| 关闭 content URI 访问 | 不合入。系统文件选择上传需要单独实测，不能以“用不到”推断；保留原设置 |
| 网络8线程、文件2线程独立 | 采纳。慢网络流不再占用文件保存线程；仍保留既有网络校验、取消、超时和响应大小约束 |
| 新媒体授权到来先拒绝旧请求 | 采纳。避免覆盖后遗留悬挂的授权请求 |
| 设备长文本 TTS 分段 | 修正后采纳。保留按句与代理对边界分段；补活动朗读ID检查，旧朗读的迟到失败回调不能停止新朗读 |

## Via 的最终范围

保留 APK 安装权限、凭据、桌面快捷方式、广播、共享目录、HTTP/HTTPS、已有字体、返回入口和系统栏处理。定位权限从最终合包清单移除；其他原有集成策略（包括既有统计与广告权限处理）不因本次需求回退。没有修改用户提供的 Via 原始二进制，DEX仅保留既有authority及校验字段改动。

## 浏览器 Agent

聊天右上角菜单 → 浏览器 Agent → 填写起始网址和任务 → 开始。使用当前角色的连接，每次任务最多12次模型调用；网页内容会传给该模型，入口明确提示。

支持打开 HTTP/HTTPS、读取正文与控件、点击、输入框/文本框/普通可编辑区域填写、选择、滚动、返回，以及系统下载和下载状态查询。模型只输出固定结构化操作，原生侧执行固定脚本，不提供任意脚本执行工具。只对当前 Via 顶层网页操作，读取当前视口的前150个控件，滚动后可继续读取；跨域iframe、浏览器设置页面、系统安装器、密码与验证码不能冒充自动完成，需用户接管。

原生能力仅暴露在受信任的本地主界面；Via网页没有 `window.Android`。会话结束或取消后不能继续发命令。首次用户输入网址直接打开；后续模型导航和修改类操作在 Via 显示原生确认（地址、操作目标与填写内容），用户拒绝则不执行；这也避免网页文本自行授权提交。控件地址/指纹变化后拒绝旧操作。普通网页回执不能携带系统下载ID/状态，下载地址必须逐字匹配已确认链接。下载排队返回pending，只有系统完成回执才记为completed；未确认完成的下载不能生成成功总结。下载仅支持网页中明确的 HTTP/HTTPS 链接，不支持 blob、POST 或脚本生成文件。停止 Agent 不会撤销已经提交给系统的下载。下载通过系统管理器保存到应用外部文件目录，可由系统下载通知打开；不覆盖已有文件。

应用被杀或任务离开后不自动重放副作用；可能已经发生的操作需在网页核对后新建任务。已有 Release `v0.0.3` 不自动包含这些源码修改，未覆盖发布资产。

## 验证与复用

```sh
node --experimental-strip-types work/qa/browser-agent.mjs
python work/qa/android-speech.py --java-dir <完整JDK目录>
```

浏览器回归使用真实Chromium DOM、模拟模型与原生回执；不调用付费服务。原生验收脚本 `work/qa/android-browser-agent.mjs` 要求明确的可丢弃模拟器、版本 `0.0.3-review` 测试APK，以及仅测试暂存中的 WebView 调试开关，命令为 `node --experimental-strip-types work/qa/android-browser-agent.mjs`，使用原生桥接真实控制 Via；不得指向个人设备或生产安装。

## 本次实测结果

- 291项核心与严格TypeScript通过；Android Vite和完整Vinext/Cloudflare网页生产构建通过。
- 144个状态 / 495项既有UI检查通过；14项浏览器Agent真实DOM与任务循环检查通过；Java TTS分段11个用例通过。
- 全新Android15可丢弃模拟器中15项验收通过：Via HTTP读取、桥接隔离、真实填写/选择/点击/拒绝、导航与返回、系统下载完成、后续导航拒绝、伪造下载地址/完成状态拒绝、任务循环、停止后关闭确认框与会话失效。模型使用fixture，无付费调用。
- Via新标签导航可能没有标准WebView历史。Agent在任务内记录已读取的网址；标准返回不可用时重新打开上一任务网址，不退出整个Via。该回退不承诺恢复表单或滚动位置。
- 模拟器最初因系统网络未验证而将下载保留pending；本轮仅在新建测试模拟器关闭网络探测并重启以使用本地HTTP fixture，最终实际下载completed。没有更改产品网络策略，也没有把排队当完成。首次启动Via的欢迎确认在测试初始化处理，产品不会自动代用户接受。
- 原签名生产候选 `yunjian-via-agent-candidate.apk`：版本 `0.0.3-via-agent-candidate` / code16，10,584,588字节，SHA256 `dd6938c076d9b102e08194894eefbd82ed4fed59547ce8c42dd85f2a78196609`。v2/v3签名、对齐、CRC、DEX及36项资源逐字核对通过，生产源码未启用WebView调试。
- 该候选未发布到Release。原生交互验收使用仅暂存中启用WebView调试的测试包，生产候选另行编译和签名校验；没有实际旧正式版覆盖升级、物理设备、真实付费模型、验证码或系统安装器自动化验收。

## 独立审核结论

### Standards

初审2项问题：导出迁移丢恢复、候选代理判断绕过守卫，相关代码暂缓。复审发现2项网页伪造下载权限/状态问题，已绑定批准的动作和确切URL、拒绝网页携带系统保留字段，并通过Android攻击回归。没有为代码气味进行额外重构。

### Spec

撤回影响Via HTTP、安装和文件分享的扩张限制，只新增禁定位。后续模型导航确认、完整目标展示、取消清理及真实返回均落实并实测；顶层网页、普通表单与HTTP链接下载范围明确，不宣称所有网站和系统操作均可自动化。

## 生产构建

完整 APK 构建仍按独立工作流执行，新增 `runtime/browser-agent-dom.js` 由资源暂存脚本显式加入 `assets/native/`，不混入历史 APK 资源清单。源码不启用 WebView 调试。构建、验收结果见本次交付证据。

架构参考：[Android WebView API](https://developer.android.com/reference/android/webkit/WebView)、[原生桥接安全说明](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)、[DownloadManager.Request](https://developer.android.com/reference/android/app/DownloadManager.Request)。外部网页保持无应用原生接口，下载完成以系统查询结果为准。
