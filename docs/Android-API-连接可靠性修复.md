# Android API 连接可靠性修复（2026-10-09）

## 诊断范围

主要检查 Android 独立 APK 的 WebView → JavaScript 网络桥 → Android HttpURLConnection → 外部服务商，以及设置页模型发现与真实聊天连接测试。**没有访问或记录设备上的 API Key，也没有连接用户的实际手机。**

### 从源码定位的故障

1. 旧 Android 网络桥允许无数据读取等待长达五分钟（Java 端 `readTimeout=300000`），JavaScript 侧无明确首响应/流空闲超时，弱网会表现为“连接卡死”。
2. 设置页曾在逐个输入 Key 后频繁发起模型列表请求；取消和失败会导致列表状态跳变，容易被误认为聊天本身无法连接。
3. 本机 API 错误（401/403、429、余额/额度、404、参数不支持、5xx）原先多数被合并成一条笼统提示。
4. 在流式回复已经启动后，如果长时间无数据，原先的错误信息会被统一降为“回复传输中断”，难以区分超时与其他中断。
5. Android 原生 DNS 安全预检查会拒绝 `198.18.0.0/15`。使用部分 VPN 的 Fake-IP DNS 时，即使 OpenRouter 或其他官方 API 的 HTTPS 实际可达，也会在 TLS 建连前被误判为内网地址。
6. 原“测试真实连接”会构造角色扮演的完整聊天上下文，包含历史与记忆。过长上下文或不兼容的角色设定会导致 Key 正常时也测试失败。

## 实施

- **模型列表**：仅已保存的 Key 自动触发一次目录发现；手动读取仍支持新填写的 Key。对列表请求设置 25 秒限制，失败时保留已有列表并提示用户手动填写模型 ID。模型列表缺失不代表 Key 或聊天接口无效。
- **官方域名的 Fake-IP 兼容**：只对内置的十个官方 API 主机名跳过预先 DNS 私网地址判定，直接交由 HTTPS 验证证书；仍然限定 443 端口、禁止重定向，所有自定义域名继续保留原来的 DNS/内网防护。不会关闭 SSL 校验，也不会把 API Key 转发到其他地址。
- **独立连通性探针**：测试按钮改为隔离的真实 `/api/chat` 请求，只用两条固定文本、128 token 输出预算，关闭不必要的采样惩罚和扩展思考，要求最终收到 `[DONE]` 才认定连通。探针不读取角色设定、历史、记忆、附件，最多等待 65 秒。
- **真实聊天**：Android 网络桥首响应超时 90 秒、连续无数据超时 120 秒；每次收到新数据后重置空闲倒计时；已完成、取消或失败都清除定时器和请求记录。
- **异常信息**：为 401/403、402、404、408/504、429、400/422、5xx 区分提示；避免在 UI 或测试输出中透露密钥/请求正文。流式超时保留诊断信息。
- **安全与计费**：绝不对聊天 POST 自动重试；用户主动决定是否重新发送，以避免生成重复消息或重复计费。保留既有域名与 HTTPS 限制。

## 验收清单

1. 无真实 API 凭据的模拟提供商测试覆盖错误状态、超时信息、流式断流和不伪造 [DONE]。
2. TypeScript 严格编译、原生 APK Java 编译、文件清单和回归测试通过。
3. 实机/模拟器人工测试：Wi-Fi/移动数据切换、网络断开、长时间无数据、服务商 401/429/404、模型目录缺失但聊天可用、聊天任务取消和重新打开页面。
4. **此修复需要重新构建并安装包含新版 `android-web/runtime.ts` 的 APK 才能在手机上生效**。仅在 GitHub 修改源码不会改变手机已安装的 APK。

## 限制

已识别的是从源码可验证的风险；无法读取真实设备日志或具体服务商的网络响应，因此不能断言每次失败都是以上原因。新代码降低卡死与误诊的概率，但无法解决服务商宕机、VPN/DNS、账户额度或无权限模型。
