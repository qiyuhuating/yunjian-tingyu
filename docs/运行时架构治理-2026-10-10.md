# 云笺听雨：底层运行时架构与健壮性治理（2026-10-10）

## 范围与依赖
本改动叠加在 P0 连接可靠性 PR #12 上，作为独立 PR #18 审核。目标是把原先散落于 React 页面里的传输细节抽成可单独测试的领域模块，先修真实错误，不对 UI、字体、插画、Via、数据库格式和签名身份做无关改动。

## 分层职责
- `app/phone.tsx`：设备状态、持久化事务调度、凭据作用域、角色连接选择、业务统计和 React 生命周期，不直接解析 SSE 帧。
- `lib/ai-messages.ts`：构造严格模型请求。固定核心提示词保持唯一的 system 字段，角色与世界书等资料以明确注明“非用户对话”的参考资料承载于后续上下文（兼容仅支持 system/user/assistant 的旧服务商）；最新实际用户请求保证为末尾 user 消息。依据角色当前模型选择可用附件，不伪称阅读未传送的文件。
- `lib/provider-adapter.ts`、`provider-transport.ts`：供应商协议、安全地址、鉴权、HTTP/标准化 SSE。网页/Android 使用同一套契约。
- `lib/ai-stream.ts`：标准化 SSE 的消费者。负责 UTF-8 分块、CRLF、跨包事件、多行 data、错误、流量限制、用量和媒体临时存储。仅遇到完成标记 `[DONE]` 方算成功；上游中断一律报错。恢复逻辑不得自动重复 POST。
- `app/chat.tsx`：群聊/私聊回合、消息持久化、呈现和用户主动重试。不得在格式校正或文本相似度判断后无提示地发起额外计费请求。
- `lib/local-phone.ts` 与备份模块：数据库事务为消息与设置的权威来源，引用的附件不因恢复提交失败而被误删。未被引用的暂存附件应通过**单独可验证的垃圾回收**清理，不能复用原先按整份恢复快照删除的危险策略。

## 不可破坏的设计约束
1. 角色连接和默认连接的密钥隔离必须持续成立；任何 API Key 不写入 PhoneState、聊天或备份。
2. 只有数据落盘成功后才发送 AI 请求；异常、取消、超时不把半截回复写成完整成功消息。
3. 正在接收媒体的数据只能暂存，完整流结束并完成实际媒体校验后才能对用户显示发送成功。
4. 原核心提示词本身不被修改，角色资料与用户历史不能篡改核心规则；后续需要就缓存命中率与不同供应商的 system 语义做专项测试。
5. 每条用户发送消息保有稳定 ID，未经用户操作不得因格式修复、文本相似度或 5xx 自动重新 POST。
6. 本机备份恢复必须保留旧记录、已有附件、已保存的角色卡及独立 API 配置；恢复失败允许有未引用暂存文件，但不得删除仍被引用的数据。

## 新增测试
`scripts/verify-runtime.mjs` 作为 `work/check-release.py` 新门禁，验证 UTF-8 + CRLF 极端碎片、多行 SSE、用量、原生媒体门禁、无 `[DONE]` 失败、无隐式重试、真实用户消息身份、群聊重复问句与备份失败不误删资产。

必须继续执行完整 TypeScript、Playwright 浏览器回归、Android 原生编译和独立 APK 候选构建。现有测试大多为可复现模拟接口，**不代表真机或真实模型质量已经得到验证**。由于本轮调整了给模型发送角色上下文的位置，真实私聊、群聊、世界书和提示词缓存应继续通过人工对照验收。
