## 计划与实现

1. 保留角色卡的身份、性格、关系、口吻和教学偏好；新增语言、编程、数学、美术、分析与教学的质量要求。闲聊短，实际任务保留必要步骤、完整代码和答案。默认中文，按用户当前语言或明确要求切换。代码以文字显示和下载，不执行未授权代码，不把角色口吻当作能力限制。
2. 群聊保留独立角色请求、其他成员的真实发言和 @。增加引用回复、可配置接话人数、自然等待和逐条发送。等待可取消；用户在等待时仍可发送文字，后续内容本地保存并排队接话。后续角色没有有意义的补充时可以保持安静。
3. 每位角色独立提取明确出现的偏好、事实与承诺，默认每四条用户消息进行一次额外模型调用。游标按角色与会话分别保存；群里未参与本轮的角色不被自动写入。原聊天仍完整保留。
4. 自动记忆必须提供现存用户消息编号和逐字证据；实际记忆保存原话，避免模型概括反转偏好。自动更正必须指定旧记录，保留五个修订版本，按原消息时间避免历史会话覆盖新偏好；手动添加和用户编辑的内容优先维护，不被自动覆盖。可查看来源、编辑、删除、按角色筛选。达到三百条上限时提示整理，不静默丢弃。
5. 保持核心和角色运行配置位于稳定前缀，检索记忆、摘要和时间放在尾部。没有照搬 Hermes 将动态记忆写入 system 的方式，以满足本应用的核心隔离要求。角色卡决定身份，最新用户更正高于旧记忆及阶段摘要，原消息可检索核对。
6. 任意扩展名的文件可本地发送和下载，单文件上限 200 MB。自动阅读覆盖文本、源码、常用 Office、ODT、PDF 文字和 ZIP 内文字；解析限 20 MB，单 ZIP 条目最多 1 MB、累计 8 MB、40 项，正文最多 18000 字。表格解析共享字符串及文件保存的公式结果，不声称重新计算。图片实际传送取决于视觉开关、格式和 4 MB 预算，最多最近两张。

## 验证与边界

103 项核心检查、严格类型检查和六组浏览器回归通过。新增检查覆盖角色隔离、伪造来源、编辑保护、更正、满库、取消、引用、静默与技术内容。浏览器回归检查真实 PDF worker、加密 PDF、中文编码、DOCX、XLSX、ZIP 限额、未知二进制保存、自动提取、编辑保护和代码下载、等待期间消息排队和停止取消。

文件“已发送”不等于模型“已理解”。本版本不解析 RAR/7z、旧二进制 DOC/XLS、加密文件、音视频正文或扫描 PDF 的 OCR；显示明确状态，并保留原文件。自动提取仍依赖接入模型的判断，逐字证据不能证明现实真实性；虚构内容应由用户核对。不能保证永不遗忘、百分之百不漂移或每次创作达到固定审美等级。实际模型调用、能力与上下文上限由服务商提供。
