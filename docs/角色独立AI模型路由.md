# 云笺听雨：角色独立 AI 连接（草稿分支）

## 产品行为

- **未设置独立连接的角色**：继承全局默认服务商、模型、地址、视觉开关与该服务商的已保存 Key；已有用户无需迁移，也不更改原聊天记录。
- **设置独立连接的角色**：在「角色设定 → 这位角色使用的 AI」指定服务商、模型及视觉输入开关。同一群聊的不同角色可以分别使用 DeepSeek、OpenRouter、Gemini、Claude、OpenAI 或已支持的其它适配器。
- **专属凭据**：可共用同服务商的本机 Key，也可为角色保存自己的 Key。每位角色每个服务商拥有独立加密 Key 槽位 `character-ai:<角色ID>:<服务商>`，切换服务商不读取其他服务商的角色 Key。
- **自定义兼容地址**：始终要求专属 Key，不转发另一自定义地址的全局 Key；地址继续受现有 HTTPS 和公网规则约束。
- **调用链**：`requestAI()` 在每轮调用开始时解析发言角色的连接和密钥；由有效服务商/模型决定上下文预算、原生音视频与视觉发送方式及 API 协议。单聊、群聊与对应角色的自动记忆整理共享这一规则。
- **全局连接测试**：始终测试设置页选择的全局连接，不能被首页角色的模型覆盖。
- **人格与记忆**：角色连接不是角色人格的一部分。换模型不修改角色卡、聊天记录、记忆作用域、来源或时间戳。

## 数据与隐私

`characterSchema.aiConnection` 只包含服务商、模型、非机密 API URL、视觉开关和 Key 使用范围；不保存 Key 明文。角色专属凭据仍通过现有 IndexedDB AES-GCM 本机密钥库保存，使用设备 Key 存取 API。普通角色卡导出不包含连接配置；完整设备备份只包含不敏感的偏好，**不携带任何密钥**。

导入角色卡覆盖已有角色时保留原有连接设置。删除角色时清除可枚举服务商对应的角色凭据。选择继承全局不删除已有专属凭据，以免误删用户保存的 Key；不再使用该凭据。

AI 图片生成、TTS、Realtime 属于独立能力接口，它们仍按已有媒体服务配置执行。角色文本模型可独立，**不代表其选择的聊天服务商自动获得独立生图或语音模型权限**。未配置能力不得声称已执行。

## 手工使用步骤

1. 进入「设置」，填写并保存可能共用的服务商 Key。
2. 进入「角色设定」编辑一位角色，找到「这位角色使用的 AI」。
3. 选服务商，填写实际模型 ID；可开启视觉能力。默认直接共用所选服务商已保存的 Key。
4. 如需与其他角色使用不同 API 账户，选择「使用这位角色自己的 Key」，保存角色设定，再保存该角色的 Key。自定义兼容地址始终如此。
5. 返回私聊或群聊；每个发言角色会使用自身连接。修改全局默认设置只影响继承默认的角色。

## 永久回归门槛

- 旧状态读取与完整备份恢复不会改变已有历史、记忆和角色卡。
- 两个角色在同一群使用不同服务商与不同模型，不修改全局连接。
- 同一服务商的不同角色可使用各自的独立 Key。
- 自定义兼容 API 不允许复用其它 URL 的全局 Key。
- 无 Key、错误 Key、上游拒绝、断流时明确失败，不悄悄切换到其它角色或服务商。
- 全局「测试真实连接」只测试全局配置；角色记忆整理使用角色连接。
- 使用 fixture 和接口回归不足以证明所有模型真实可用；正式发布前必须按账号权限验证实际接口与真机。

## 发布边界

此分支基于 PR #1 的开发草稿，不含新签名 APK，不修改完整内置 Via。必须先通过源码检查、浏览器回归、存储/备份验证，再审查合并；不能直接把现有历史 APK 当作新功能包。
