# 云笺听雨 0.0.1 · 核心提示词隔离

## 计划与验收

1. 统一聊天与实时通话的核心规则，保留既有身份、年龄、简短回应、群聊、共演、附件真实性约束。验证：改变角色、资料、时间和聊天模式后实际系统字段保持同一字节内容。
2. 角色卡、世界书、个人资料、历史、摘要作为独立资料；新增成年自主、同意的性相关表达与正当创作、政治及社会争议讨论条款。验证：卡片中的“忽略系统”等文字不能拼进核心字段。
3. 回归文字与语音路径、签名 APK、资源核对、源码归档及私密 GitHub 发布。验证：当前测试通过、随包字节一致、证书不变、发布下载摘要一致。

## 实现

`outputs/mori-phone/lib/system-prompt.ts` 提供 `CORE_SYSTEM_PROMPT` 与明确版本 `0.0.1-core.2`。该字符串只依赖源代码中的固定群聊规则，不读取角色卡、世界书、聊天、时间、用户姓名或设置。原始默认常量不受资料修改影响。新增 `coreSystemPrompt` 本机设置，只有用户在“设置 → 核心系统提示词”主动保存后才改变实际核心；未保存草稿与载入默认到编辑框都不会自动覆盖。空白核心不能保存，原始版本可随时载入并保存。完整备份会保存这项设置，角色卡导入仅改变角色。

本次是一次有明确内容差异的核心更新，之后各个角色聊天模式使用同一份用户已保存的核心，默认保持原始内容。保留原有规则的行为要求，补充了资料隔离和争议话题条款。没有把“任何性内容都必须无条件生成”写入核心；新增条款限定成年人、自愿与合法，未成年角色仍可参与非性化角色互动。

文字请求依次发送：唯一固定 system、JSON 运行配置消息、历史消息、当前用户消息与记录资料。角色字段仍完整保留，包括补充说明及 post-history 文本；它们不会成为实际 system 消息。世界书命中仍按关键字、作用域和排序选择，移到记录资料中。模板先在各字段展开，再 JSON 序列化，名称含引号或换行也不会破坏结构。

OpenAI / 兼容接口、Anthropic `system` 及 Gemini `systemInstruction` 都只映射固定核心。实时通话 `instructions` 同样只含固定核心；角色与按语音模型窗口选择的历史通过 `conversation.item.create` 数据通道消息独立发送。用户内容为 `input_text`，既有助手文本为 `output_text`。参考 [OpenAI Realtime 对话文档](https://developers.openai.com/api/docs/guides/realtime-conversations) 与 [客户端事件规范](https://developers.openai.com/api/reference/resources/realtime/client-events)。

事实摘要保留原有独立 `SUMMARY_SYSTEM_PROMPT`，只提取事实，不扮演角色；不与角色聊天核心合并。

## 优先级、缓存与验证边界

固定核心约束 → 用户当前明确要求 → 角色与可编辑预设 → 世界书、摘要、历史资料。角色年龄、口吻和默认长度仍读取卡片，用户不必每轮指定。群聊默认短消息，普通问题可以分几条回答；重要说明允许较长，保留角色身份与无旁白格式。

同一份已保存 system 与位于历史前方的角色配置保持稳定前缀；时间、世界书命中、召回和本轮记录位于后段。修改人设应使配置部分失效，不能为追求缓存保留旧设定。缓存命中量继续读取服务商实际 usage；没有真实 Key 时不声称实测了更高命中率。

103 项核心检查包含角色卡与模式变化、用户明确保存核心、旧备份默认迁移、1M 预算的 600 条 / 600K 文字实际请求、OpenAI / Anthropic / Gemini 实际系统字段、Realtime 消息角色/类型分离。6 组浏览器回归覆盖 24 个应用入口；群聊流程为 25 类，其中新增实际语音组件初始化请求核对、转写保存、静音和挂断释放麦克风。语音和外部接口使用明确标注的测试响应，不是已完成真实通话的证据。

固定系统字段的字节隔离可以由代码测试证明；模型是否遵循指令仍受服务商、模型和上下文影响，不能把字段隔离称为绝对防提示注入。另已在 Android 15 / WebView 124 模拟器完成实际安装、内置 Via 浏览、返回与本地日记持久化验收；没有真机、真实麦克风和真实 API Key 验收。

## 默认最长上下文

模型列表不仅读取 ID，还解析 DeepSeek 的 `context_window`、Gemini 的 `inputTokenLimit`、Claude 的 `max_input_tokens`、OpenRouter 的 `context_length`，并保留输出限制。元数据按服务商 / 自定义地址 / 模型保存，不在不同地址之间串用。实时值优先于官方静态预设。官方预设已核对 [DeepSeek Models](https://api-docs.deepseek.com/api/list-models/)、[GPT-4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)、[GPT-5 Mini](https://developers.openai.com/api/docs/models/gpt-5-mini)、[Claude 模型概览](https://platform.claude.com/docs/en/models/overview)、[Grok 4.7](https://docs.x.ai/developers/models/grok-4.7)、[Qwen Plus](https://docs.modelstudio.console.alibabacloud.com/ja/model-studio/qwen-plus)。原生字段格式另见 [Gemini Models](https://ai.google.dev/api/models)、[Claude Models API](https://platform.claude.com/docs/en/api/models/list) 与 [OpenRouter 模型列表](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。资料核对日为 2026-10-07，不宣称静态预设永不变化。

默认“模型最长可用上下文”，支持百万窗口的模型采用其实际值，而非统一假设 1M。未披露且无官方预设的模型明确显示 32K 保守回退；可手动填入服务商真实值。手动预算不会超过已经确认的模型上限。

每次为正文、四档思考、核心、人设、动态资料和图像另留额度。UTF-8 字节用于保守的文字 Token 估算，不是模型精确分词结果，通常会少装一些文字；计费仍看服务商实际 usage。窗口不足以容纳当前资料时明确报错。历史按预算保留到最近一条，超出窗口的原记录仍在本机，可供摘要和相关召回。

移除了固定约 64 条历史、100 条传输消息、400K 总文字及逐消息旧字符预算。传输仍有显式资源边界：最多 100010 条、16Mi 总文字字符，网页 JSON 请求 64MB。不自动往上下文填充无关资料，长窗口也不增加正文回答长度。

实时通话按其自己的模型预算选历史，默认 GPT-Realtime-2.1 的 128000 窗口，避免把文字模型的 1M 上限套给语音模型。语音输出预算实际发送 `max_output_tokens`，保留短回应。参考 [实时模型资料](https://developers.openai.com/api/docs/models/gpt-realtime-2.1)；语音历史不再固定只取十二条。
