## 计划

目标是让人物设定、世界背景、实际聊天、现实长期记忆和剧情连续性各司其职；角色既能聊天，也保留文件分析、代码和数学的完整任务能力。Via 合包设计继续保留。

## 决策

研究源版本为 SillyTavern `release` 提交 `06bde939fb1e9c4c8d8641d810f0a916b5bce127`。读取了以下源码：

- [characters.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/src/endpoints/characters.js)：角色卡导入与格式转换。
- [character-card-parser.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/src/character-card-parser.js)：PNG 内嵌卡处理。
- [memory/index.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/public/scripts/extensions/memory/index.js)：与聊天消息位置关联的摘要机制。
- [LICENSE](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/LICENSE)：AGPL-3.0。

本轮复用其格式约定和适合的设计，独立实现云笺模块，没有复制或捆绑 SillyTavern 源码。其世界书模块依赖大量 UI、全局状态和提示词注入系统；整体移植会引入不适合移动本地客户端的耦合。本轮也没有新增依赖。

| 设计 | 云笺取舍 |

| 世界书常驻和触发 | 主词＋AND ANY/AND ALL/NOT ANY/NOT ALL；英文大小写/整词；中文文字匹配；模板词；可调扫描深度 |
| 世界书递归 | 显式启用，直接扫描后最多三轮扩展；已选条目不重复；支持禁止被递归触发和禁止触发其他条目 |
| 世界书预算 | 按角色实际连接窗口，默认输入预算 12%、最多 2048 估算 tokens；完整条目选取，过大的条目跳过并说明，不从中间截断 |
| 前后背景 | 角色资料前和历史后两种资料位置；仍作为背景资料，不增加系统权限 |

| 自动更正与并发 | 先验证全批；角色记忆和游标发生变化时拒绝旧任务；满库全批拒绝；时间检查点防止已整理消息删除后重扫全部历史 |
| 人物风格与功能 | 不以预设把角色统一成温柔/恋爱/服务人格；代码、分析、教学仍保留必要步骤和交付物 |

## 执行

1. `lib/card-analysis.ts` 将人设分成最多160个可完整重组的原文单元，接受最多80段连续分类。单元编号由本地生成，避免依赖模型计算字符偏移。AI 请求只有分类系统指令和当前卡的正文，不发送私聊、世界书、长期记忆；沿用所选已有角色的真实连接和加密密钥。
2. `app/card-analysis-preview.tsx` 支持选择分析连接、预览人物和新世界条目、失败保留原文、取消及卸载中止。分析失败不阻挡直接导入。新增导入原卡下载入口，拆分后的当前卡与原卡分开。
3. `lib/world-info.ts` 是实际发送和界面测试共用引擎。1000条世界书上限、完整关键词选取、扫描缓存、作用域隔离、完整条目预算及有限递归。世界书界面可独立导入 SillyTavern 数组/对象 entries、检查、导出、搜索、编辑与解释命中；长列表每次显示60条。
4. 导出保留未知原字段和扩展；未编辑的长原字段继续用于导出。支持的规则改动可正确导出和重新导入。单个角色原始档案最多100万字符；单次文件4 MB。运行字段正文仍有18000字上限，超长字段在导入预览中告知；不声称运行时使用全部长原文。
5. `character-memory.ts` 对提案来源、整条来源消息中的凭据、角色归属、时间、任务基线和游标进行验证；在副本上准备全部更改，成功后一次提交。锁定/手动记忆继续由用户维护。旧备份自动补 `memoryWatermarks`，不改变已有聊天核心。
6. `chat-maintenance.ts` 校验摘要任务的每条原消息；消息被编辑、删除或标成失败时不提交旧摘要；空白摘要不消耗游标。`use-editor-draft.ts` 处理编辑器键变化并拒绝上一编辑器的迟到回调。
7. 摘要整理器明确按本次任务选择 JSON 数组或普通条目，避免固定的条目输出要求与长期记忆 JSON 契约冲突；这只调整后台整理器，不改用户保存的聊天核心。
8. 现有媒体及角色 AI 浏览器测试改为定位最终消息，避免同时匹配流式占位和已保存消息；刷新前显式验证真实持久化流程，避免测试通过时间猜测磁盘写入完成。

### 兼容边界

保留但不执行的 SillyTavern 行为包括：深度/示例/作者注插入位置、正则关键词、概率和定时效果、第三方脚本、V3 装饰器、CHARX 及外部媒体资产获取。导入时提示可识别的不支持规则；默认退回普通字面匹配/背景位置，原始规则保留用于导出。不能把此实现称为完整 SillyTavern 兼容。

AI 对片段的**语义分类**仍可能不正确，完整原文校验只能防删改、遗漏和重复；因此必须检查预览并可恢复原卡。世界条目属于何人、采用哪些关键词及是否常驻仍是可编辑选择。

新增时间检查点优先用于已升级任务。旧备份仅有游标且该原消息已经不存在时，首次只检查最近一个提取间隔，不回放全部历史，之后使用新的时间检查点。

### 发布结论与后续门槛

结论：本轮源代码与本地接口流程通过验收，提交为接续 PR #2 的草稿。历史正式APK、Via二进制和随包资源保留原版本，当前下载APK不包含新功能。首轮 GitHub CI run 37877366840 已全部通过，包含历史资源完整性和原 APK 校验；之后的后台整理器格式修正还需以新提交的CI结果为准。

正式发布前仍需：真实 API 下多角色/多模型的长对话评测、人物一致性与现实/剧情分离评测、真实网络中断及限流测试、沿用原签名重建APK，并在Android真机验证导入、后台切换、权限、录音和Via往返。源码检查无法保证接入模型的角色扮演质量或永不产生记忆漂移。

完成门槛后再替换正式下载资源。CHARX、语义向量检索、完整ST深度插入/定时规则和后台系统闹钟属于可单独验收的后续能力，不能在当前界面宣称已接通。
