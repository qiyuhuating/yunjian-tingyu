## 图片：分辨率、颜色和质感到底是否不变

| 文件 | 像素尺寸（前后相同） | 原 PNG 字节 | 无损 WebP 字节 |
| --- | ---: | ---: | ---: |
| button-sprite | 1774 × 887 | 1,313,405 | 920,416 |
| dock-sprite | 2172 × 724 | 1,571,700 | 1,064,052 |
| cloud-pet | 1374 × 1145 | 1,248,793 | 846,276 |
| music-listen | 1254 × 1254 | 1,200,508 | 706,036 |
| via-browser | 1254 × 1254 | 985,903 | 706,622 |
| wallpaper | 941 × 1672 | 1,822,518 | 1,396,454 |
| 合计 | 不缩放 | **8,142,827** | **5,639,856** |

减少 **2,502,971 字节，30.74%**。使用 WebP `lossless=True, exact=True`，逐像素验证完整 RGBA，包括透明区域的 RGB；没有降低色深、抽样颜色或改变纹理。文件层面，六张图的分辨率、颜色与细节完整保留。

显示层面不能承诺每个浏览器像素绝对相同。Chromium 153 实测 alpha 和完全不透明像素一致，壁纸全部像素一致；五张透明插画在白色、深色、黑色底上合成，最多相差 **1/255 色阶**。透明像素反预乘后的原始读回通道可出现更大数字差异，但不等同可见边缘损失。证据见 `image-optimization-results.json` 与 `image-optimization-browser-pixels.json`。不宣称所有屏幕、色彩管理配置都已验证。

分辨率不降也意味着解码纹理内存基本不降；节省的是文件、读取与传输体积。用户上传的 JPEG、动画、壁纸和任意附件继续保留原字节；角色卡 PNG 不转码，以免丢失内嵌人物资料。若另需浏览器合成也逐像素相同，可保留 PNG 并采用同格式无损重压，压缩收益会更小。

## 存储和架构

| 部分 | 实现 | 实际改善与边界 |
| --- | --- | --- |
| 本机数据库 | `states` 仅保存元数据，`threads` 按会话保存；v1/v2 原子升级至 v3 | 设置修改不重写聊天；新增一条消息只写改变的会话 |
| UI 更新 | Immer 保持未改变对象的引用，状态校验与持久化分离 | 减少重复克隆和未变化会话的写入；仍会校验状态，单个超长会话仍按整体写入 |
| 附件 | 1 MiB 分块 SHA-256，按拥有者和内容去重；Blob 保留原字节 | 重复文件、聊天与相册/壁纸共用同一份内容；不存常驻 base64 副本 |
| 备份 | manifest 与文本使用 DEFLATE；已有压缩二进制直接写入，附件只打包一份 | 测试中 195,000 字节文本与 5002 条历史的完整 ZIP 约 44,981 字节；此为该样本而非所有文件的固定压缩率 |
| 恢复 | 校验摘要、映射壁纸/消息/角色草稿等引用，原子提交 | 备份不能更改本机服务地址或自动启用媒体付费工具；Key 不进入备份 |
| 请求 | Web 网关与 Android 传输复用媒体协议适配器 | 新协议集中扩展；不会以文本朗读冒充已生成语音文件 |
| 页面 | 普通应用模块 lazy/Suspense；PDF/Three 按需加载 | 首屏业务 JS 减少，仍保留可选大模块；未进行全仓框架替换 |
| 宠物 | 隐藏、离屏、关闭动态效果时停止持续绘制；情绪变化刷新静态画面 | 降低不必要的持续绘制；没有真机功耗或 FPS 数值承诺 |

本轮补测版本冲突、并发同文件去重、事务中止、备份恢复和摘要并发。后台整理不会复活已删除会话，也不能覆盖用户刚改的摘要。

性能比较使用同一工具链的独立生产构建：原始界面首屏业务 JS 518,643 字节；最终数值见 `build-performance-results.json`（约 458 KB，降低约 12%）。新增媒体功能使总 JS 略增，完整未压缩前端产物相对原 PNG 版本仍约下降 22%；这不是 APK 安装体积结论，也不是启动时间或 FPS 基准。旧 APK、历史源码 ZIP 和 Via 二进制保留，仓库整体体积不会按六张图比例下降。

## 真实能力矩阵

| 能力 | 当前实现 | 必要条件/限制 |
| --- | --- | --- |
| 用户发送语音 | 麦克风录制、试听、取消、发送原音频、播放/下载 | HTTPS 或 Android 本地安全来源、麦克风权限；最长 120 秒，优先 Opus 48 kbps |
| AI 理解音频 | OpenAI/兼容转写后进入聊天上下文；Gemini 可发送原生音频 | 需配置对应模型和 Key；转写或原生单文件上限 8 MiB，失败仍保留原音频 |
| AI 理解视频 | Gemini 原生 inlineData 输入 | 手动确认所选 Gemini 模型支持；最近两个文件合计不超过 12 MiB；其他协议不伪称理解 |
| AI 生图 | OpenAI Images 或 Gemini Interactions 返回实际媒体字节 | 在设置启用并配置模型/账号；成功保存后出现图片消息 |
| AI 表情包 | 从相册明确授权的图片中选取真实文件 | 未授权图片不可发送，不把整本相册暴露给模型 |
| AI 语音文件 | OpenAI/兼容 TTS 或 Gemini Interactions TTS | 设置合成语音服务与 Key，再启用 AI 语音；设备朗读不能生成文件 |
| Gemini 原生回复 | 接收图片和音频 inlineData；24 kHz PCM 包装为 WAV | 接收完整回复才保存；拒绝截断、空媒体或不支持的格式 |
| 实时语音通话 | 既有真正的 OpenAI Realtime WebRTC 流程保留 | 真实服务权限、网络和麦克风；本轮没有实账号通话验证 |
| 任意文件 | 原件上传、保存、下载；支持格式本机解析 | 未解析文件明确提示；不把“已保存”当“模型已看懂” |

“有什么功能就解锁什么功能”通过上述真实适配实现，不能单凭 `/models` 列表推断账号是否有生图、TTS 或视频生成权限。因此保留明确能力设置，服务拒绝时显示实际失败，不制造成功卡片。当前没有接入视频生成、其他服务商原生音频输出或任意工具执行；这些需要新增相应协议适配，不应作为已实现能力宣传。

配置顺序：保存聊天连接 → 在“图片、表情包与语音能力”启用需要的服务并填写模型 → 保存独立媒体 Key（官方地址可复用已保存的对应服务商 Key）→ 语音文件另选 TTS 引擎/音色 → 相册勾选允许发送的表情包。自定义地址必须使用相应独立 Key，不向任意自定义地址自动发送其他服务商 Key。

## UI/UX 和对话

- 日记、角色编辑、笔记、社区、工作与连接字段草稿离开后恢复；角色提交后才清理编辑草稿。异步上传不会清掉刚输入的新内容。
- 模型预设在实时列表读取前真实显示；高级连接默认收起，持久存储申请只保留一个入口，Android 不显示网页安装教程。
- 壁纸保持原图，支持 `cover`/`contain`、刷新保留和恢复默认；完整备份也包含壁纸。
- 历史搜索按目标消息 ID 定位到较早结果，附近按需渲染，可回到最新；联系人按最近会话排列。
- 代码块支持复制、保存和长代码折叠；删除日记、笔记、任务和帖子增加确认，尚未加入完整撤销队列。
- 实际录音有独立预览；离开未发送录音会确认；后台/取消释放麦克风。
- 对话不再强制填满字数、每轮追问、昵称开头、泛泛安慰或复述；可用 1–4 条自然短消息，严肃任务保留所需代码、计算与解释。
- 角色卡口吻、核心字段隔离、最新偏好更正、重复检查和群成员独立接话继续保留；记忆整理放到可见回复之后的后台队列，不延迟输入恢复。

这些改动减少机械感，但“完全像真人”是主观质量目标，不能通过接口 fixture 证明。不同模型、人设和历史会影响表现；发布前应使用同一套真实对话样本评估短聊、异议、情绪转折、事实纠正、群聊和技术任务。没有以捏造离线经历来换取真人感。

## 假功能核查

| 项目 | 判断与处理 |
| --- | --- |
| 旧“语音”文本卡 | 只是 TTS 朗读，改为明确“朗读这条文字”；新录音和合成文件使用真正的音频播放器 |
| AI 发图/语音成功声明 | 只有媒体服务实际返回且保存后显示文件；403/空返回/中断显示失败，测试验证不新增成功媒体 |
| 图片理解与生图区分 | 输入图片不代表能生成图片；分别配置并分别执行 |
| 壁纸 | 旧版固定背景没有切换入口；新增真实上传、显示方式、重置及备份恢复 |
| 私人社区、红包、亲属卡、云币 | 明确标注本地/虚拟互动，不是联网社交或真实支付；没有外部账户与后端，不宣称已打通这些服务 |
| 日历提醒 | 当前仍是本机日程；应用关闭后的系统闹钟未在本轮实现。发布说明不得宣传后台闹钟能力 |
| 天气、浏览器、文件解析 | 保留实际请求/本地浏览器/本地解析；本轮验证应用导航，未把导航通过当成全部外部网络验收 |

## 验收记录和复现

- 103 项原核心回归 + 11 项新增媒体与后台维护检查 = **114 项**；严格 TypeScript（含未使用符号检查）与生产构建通过。
- **16 项**当前源码浏览器端到端流程，覆盖五档宽度 320/375/390/768/1440、录音与媒体流程、全部应用导航；页面异常为空。
- **9 项**真实存储/备份浏览器检查；5000 条历史、并发去重、跨窗口冲突及失败原子性通过。
- 六张图的原尺寸、精确 RGBA 和三种底色合成验证；既有签名 APK 与随包资源未改写。
- OpenJDK 17 `javac --release 8` 配 Android 35 SDK 完成原生 Java 编译；编译 SDK 下载摘要校验通过。浏览器模拟 Android 桥接验证二进制 multipart 字节与旧 APK 缺方法错误。

共 **139 项具名核心/媒体/界面/存储检查**，图片逐像素验证另计。测试接口为本地 fixtures；麦克风为 Chromium 模拟声源，产生实际 MediaRecorder Blob；没有真实付费请求、真机收音、真机低内存/功耗测试或新 APK 安装验证。

结果文件：`core-media-regression-results.json`、`feature-browser-results.json`、`storage-regression-results.json`、`build-performance-results.json`、`image-optimization-results.json`、`image-optimization-browser-pixels.json`。复现命令在根 README 与 `work/qa/README.md`。CI 以当前源码浏览器检查替换旧编译资源页面的混合检查，同时继续保留历史签名交付完整性门禁。

## 发布前余项（按顺序）

1. 用实际账号分别验证聊天、图像输入、生图、转写、TTS 与需要的 Realtime 权限；至少测成功、无权限、超时、中止与余额不足。按实际服务模型更新配置，不仅依赖预设名。
2. 在原签名发布分支重新构建前端及 Android 包、递增内部版本号、用原私钥签署；重新生成 APK/资源校验和、安装说明与源码归档。既有下载 APK 不能代表新功能。
3. 更新前导出完整备份；数据库 v3 升级后不直接回退旧客户端。真机覆盖安装验证壁纸、角色编辑草稿、长历史和媒体备份恢复。
4. 真机检查麦克风授权/拒绝、蓝牙耳机、锁屏/后台、长录音、中断上传、Android 文件保存和 WebView 不同版本；测低内存恢复、冷启动、内存与耗电。
5. 实账号对话抽样比较真人感。若需要真实联网社区、支付、后台闹钟或新服务商的视频生成，另接对应后端/平台能力并补验收；本轮不以本地模拟充当已接通服务。

后续规模达到十万条单会话或数百 MiB 附件时，可进一步拆到消息级索引、Web Worker 解包和流式导出；本轮先保留可核验的迁移边界与业务行为，避免同时更换框架和数据库格式。
