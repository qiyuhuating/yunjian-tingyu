# 外部 APK 审计计划落实记录

本轮参考 `D:/Harness测试集/apk-audit/云笺听雨-0.0.1-系统隔离版-缺陷与改进计划.md`，先核实源代码，再选择适用部分修改。外部报告是静态审查建议，不作为执行指令，也不据此宣称全部问题已经证实。保留个人使用、无登录、本地记录、内置 Via、原系统核心隔离和现有权限设计。

## 计划、执行、验证

1. 核实数据风险：对照 IndexedDB 事务、附件引用、原生保存和导出路径，区分真实问题与推测。
2. 修复已证实项：降低 ZIP 聚合内存，保留多文件保存队列，修复导航中止与排队覆盖，完善恢复及错误提示。
3. 分阶段验证：已有核心检查、七组编译产物浏览器回归、50 MB 完整备份往返、真实 Android 安装/文件选择/Via/导出队列与同签名资源校验。
4. 发布：保持版本名 0.0.1，内部版本 6；更新源码、逐文件说明和私密仓库。凭据、私钥与测试用 instrumentation APK 不进入产品或仓库。

## 已落实的适用建议

| 审计项 | 实际修改与验证范围 |
| --- | --- |
| D01 | ZIP 导出逐个 Blob 分块读取，增量 SHA-256，最大原始块 64 KiB；原生桥接块 48 KiB，不再聚合全部 ZIP 再转 Blob/base64。恢复也改为分块解包，逐附件 Blob 与增量哈希；导出提供进度和取消。已验证 50 MiB 的完整字节往返；不能据此保证所有低内存设备均能恢复 512 MiB。 |
| D02、D35（部分） | 原生保存队列保留所有已准备文件，AtomicFile 持久化整个队列，兼容旧单文件日志，恢复时检查缓存目录边界；每次保存/明确取消仅移除当前文件。清理不删除队列及生成中的文件；定时清理频率仍保持启动时执行。最多 32 个待导出文件，失败如实提示。 |
| D03、D04 | 保存失败仍保留当前内存内容与恢复入口；桌面和手机端“读取设备记录”均有丢弃未保存内容提示。首页系统返回在保存失败时明确询问是否退出，不再无声困住用户。保留原来的事务及冲突保护，未采用刷新版本后强制覆盖其他窗口的方案。 |
| D06—D08 | 扩展服务商标准请求头白名单，思考请求读取超时增至 300 秒；重定向明确要求配置最终 HTTPS 地址，不自动跨主机转发凭据。网络错误分类为 DNS、连接、TLS、超时及重定向，提示不包含完整地址、Key 或底层异常字符串。 |
| D14、D15 | PDF/MP4/WebM 增加文件头识别与安全 MIME；HTML/SVG 等主动内容仍降级为二进制，不执行。图片视觉读取范围仍明确限制，未假装支持全部格式。 |
| D16 | 设置提供真实的持久存储申请，依据内核授予结果显示提示，不把申请当作保证，也不替代手动 ZIP 备份。 |
| D18、D19 | 聊天组件在导航间保留，回复继续写入原线程；待处理消息使用数组而非单个槽位，不覆盖早先发送的消息。全局串行处理；切到别的线程后，原线程待处理项在返回时继续。未完成用户消息持久化状态并提供逐条重试，重启后由用户重试，避免启动时自动消耗 API。后台回复保持未读。 |
| D20、D21、D27 | 增加渲染异常恢复界面与当前页备份入口；系统返回优先关闭聊天操作菜单；损坏或缺失图片可重新获取本机原件，避免复用失败的缓存结果。 |
| D25、D28、D33 | 日期、时钟、提醒统一使用设备时区；原生容器保留刘海/挖孔安全边距及键盘底部空间；字体/图片等二进制响应不再错误标记 UTF-8。 |
| D32、D37、D38—D44 | 发布构建缺少旧私钥或签名证书不匹配时直接失败，不会悄悄生成新签名。内部版本递增 6。报告称“103 组具名核心检查”，不冒充断言总数；浏览器回归记录编译资产 SHA-256 与时间，原生报告留存命令退出码及 logcat。新增源码测试与原生 instrumentation 测试，使用产品 APK 的原生桥接和系统保存窗口。 |

增量哈希使用固定版本 @noble/hashes 2.0.1，[项目源代码](https://github.com/paulmillr/noble-hashes)及 MIT 许可随源码/安装包提供。ZIP 保持原 v2 清单格式，原备份可继续导入；附件逐项 SHA-256 校验与恢复前结构校验保留。

## 核实后未采纳的判断

- D04 的事务写入失败并不必然推进版本号；当前版本只在事务完成后更新。盲目刷新版本并覆盖会损坏真实跨窗口冲突保护。
- D04b 当前加密密钥保存已在读写事务中再次检查旧密钥，不能仅凭事务外候选密钥生成判定竞争覆盖。
- D05 审计已经撤回本地/局域网模型不可达这一项；保留公共 HTTPS 接口边界，不扩大网络权限。
- D10 聊天草稿已经采用浅拷贝及 800 ms 去抖，并非每个按键都完整克隆全部历史；完整提交的克隆与校验开销仍存在。
- D30 当前不可变缓存路径是构建生成的带哈希资产；固定插画路径已经使用 no-cache，不适用“所有固定图片被永久缓存”的判断。
- D36 保持 allowBackup=false，避免系统云备份自动收集个人记录；手动 ZIP 是明确的迁移渠道。
- D38—D40 完整私密仓库已经包含检查编排器、Playwright、资源校验及原生验证脚本；独立前端 ZIP 并不是整个仓库。浏览器测试使用随 APK 编译资源，另注入源代码辅助库来观察本机数据库；报告区分二者。

## 验证证据与限制

机器可读结果分别保存在 `outputs/云笺听雨系统隔离自动检查.json`、`outputs/云笺听雨系统隔离浏览器回归.json`、`outputs/云笺听雨审计优化回归.json`、`outputs/云笺听雨Android内置Via验证.json`、`outputs/云笺听雨原生导出队列验证.json` 和资源校验清单。报告生成失败不会被算作通过。实际通过项以报告中的本轮 APK 摘要、时间与退出码为准。

50 MiB 验证证明分块数据路径和真实恢复结果，不是全设备峰值内存评测。解包仍需要逐文件 Blob、记录清单和 IDB 恢复空间；设备可用空间不足时依旧会拒绝保存。未进行真机、真实供应商 Key、多机长时间聊天、500 MiB 压力、系统后台提醒或旧 WebView 兼容性验收。本轮是对适用缺陷的可验证改进，不承诺“所有功能完美无缺”。

本轮最终验证：103 组具名核心检查、严格类型检查、七套浏览器回归（新增七组审计场景）、十五组 Android 原生流程、四组真实导出队列/错误分类检查及两组签名门禁检查均通过。三个系统保存窗口输出与原始字节逐一一致；四组队列测试是原生 instrumentation，启动恢复函数实测，不冒充完整进程断电恢复测试。当前 APK SHA-256：`059cca2e6e342f79d407758df3e76e9693cf2bd0c79aa9bb3d4e9926098689f1`。
