# UI/UX 与真人式群聊调优

参考上游 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)。已读取 SKILL.md、pro-rules，并检索触控尺寸与 React 焦点管理建议。设计系统检索给出的营销页结构和字体不适合既有小手机，因此没有套用；保留 Source Serif 4、绘图资产和天空留白，采用与手机操作相关的建议。

1. 审视 → 核对页面、触控区域和操作实现。已发现聊天工具 36px、双返回栏、输入身份固定为首成员、朗读入口易被理解成通话、图片点击直接导出等问题。
2. 实现 → 统一聊天导航、48px 主要操作区域、图片原位预览及保存、明确真实通话入口；群聊使用独立提示词、发言轮换、@、成员管理、角色身份与群记忆隔离。
3. 验证 → 72 项核心检查与严格类型检查；原四组浏览器回归及新增群聊/界面验证。检查浅暗主题、320/375/390/768/1440、横屏、缩小可用高度、字体放大、减少动画、实际按钮反馈、图片键盘关闭、数据刷新恢复。
4. 交付 → 构建独立 APK，沿用原签名与包名，版本仍为 0.0.1，Android 内部版本号递增以覆盖安装；检查 APK、源码、许可证与随包资源的一致性。

群聊通常每条 5—40 字，最多 60 字，每次 1—3 条。默认两位成员接话，轮换覆盖完整成员名单；@ 指定成员和 @所有人可明确指定发言者。这是产品节奏设定，不是微信用户行为统计。剧情角色卡只保留性格和口吻，群聊不使用剧情预设、动作旁白或接话选项。输出不符合常见格式或长度规则时先重写，仍不合格则保留已有消息并提示重试。

检验中的模型、天气和原生桥接使用可控测试响应，用于验证软件行为；真实模型遵循程度、真实音频与手机系统兼容性仍需要机主的 Key 和设备实测。虚拟云币与私人剧情功能明确标明用途，不能视为真实支付、公开社交平台或视频直播。
