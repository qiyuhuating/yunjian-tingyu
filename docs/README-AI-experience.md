## 1. 调用思路

先把任务转成可观察结果：审核对象不漏项、每项有采纳依据、失败场景先复现再修、新APK能够通过签名/包身份/资源核对、源码包能重新构建、经验文档能指导下一次执行。用户确认未合并 PR 也在范围后，读取 GitHub 元数据和固定提交，不把“最新”当永久不变的分支名。

用 GitHub 插件取得私有仓库、PR说明、分支差异、初始文件内容和上游验收证据；本地执行承担源码处理、类型检查、浏览器、原生打包及归档。初始文件按 Git blob SHA 校验，本地缓存只有摘要一致才复用。续做时重新查询远端，发现主线新增修复和PR33，保存旧工作后创建新 worktree，以新主线重整。

应用 `code-review` 技能要求的两名只读审阅代理：Standards 对照项目规范和数据契约，Spec 对照PR原始要求与真实行为。主执行者负责复现、代码修补、取舍及最终结果，审阅意见不是执行证据。两个轴保留各自报告和计数；互相补充，但不凭票数决定正确性。

## 2. 关键决策节点

| 节点 | 依据与决策 |
|---|---|
| 是否将所有分支直接合并 | 否。先查祖先和实际能力；已合并或被替代的分支不再次覆盖，旧#10会放宽DNS与空响应判断，暂缓其原实现 |
| RC3还是最新主线优先 | 保留最新主线的待写Blob、紧急备份、分段备份和完整原文记忆，只叠加RC3原子交付、哈希、次数上限与同次产物验收 |
| 测试失败是否改产品默认值 | 否。PR33单角色是明确需求；测试显式造多角色旧记录，不为通过测试恢复15默认角色 |
| 如何判断保存成功 | 看IndexedDB落盘与刷新后原字节，不看React乐观状态或错误条隐藏 |
| 能否引用旧升级成功 | 否。升级结论绑定本次源提交、APK摘要和实际安装；当前仅完成身份与结构核验 |
| 是否更换签名/降低版本码 | 否。复用独立版证书，code14高于已知code13；不生成替代证书 |
| 如何交付前端 | 用主线依赖驱动导出器，保留动态模块和预览，排除后端、历史材料及开发缓存；不把React源码称为可双击HTML |

## 3. 遇到的问题与对应解决方案

| 问题 | 解决及验证 |
|---|---|
| Git直连/本机gh配置无法取私有源码 | 先用GitHub插件取得固定对象；后使用已配置Git凭据管理和系统HTTP代理完成认证读取，不在日志打印凭据 |
| 一次工具调用源码数据过大 | 将内容保存为本地数据文件，由短脚本读取；限制单次输出，不把长源码和Base64反复塞进上下文 |
| 媒体保存失败后重试没有Blob | 故障注入先复现RED，保留待写Blob，重试同事务写入；实际按钮、1次模拟服务调用、刷新后原图逐字GREEN |
| 满额聊天仍改回执 | 在beginTurn修改前守卫；验证0请求、0成功提交和回执全等，仍允许最后一次合法重试 |
| strict记忆schema拒绝已存hash | 恢复可选sourceDigest并与新完整原文策略兼容；新旧格式、锁定修订和否定语境共同回归 |
| 默认角色精简后QA崩溃 | 明确设置测试角色和线程；保留旧记录迁移断言，视觉用新默认云汐 |
| 插画模板路径被裁剪遗漏 | 显式完整URL映射；测试真正进入APK的暂存目录，验证14张图解码与零404 |
| 隐藏聊天容器让溢出断言假通过 | 将检测对象限定为launcher所在可见容器，要求非零宽度再比较scrollWidth |
| 保存恢复测试过早reload | 错误条在saving也会消失；等待数据库出现完整附件记录再刷新，保留原字节断言 |
| aapt2中文输出路径失败 | APK生成与资源合并放入ASCII物理目录，源码仍在原工作区；SDK按需通过ASCII路径访问 |
| 本机JDK无法编译--release8 | 保持项目编译参数，换用本机完整JBR25.0.4，真实打包成功；不删校验掩盖环境问题 |
| CRLF/EOF导致空白检查失败 | 只修本轮新增行与EOF，保留原格式；类型/行为回归和最终空白门槛通过 |

## 4. 可复用实践

1. 每个调用先明确要取得哪项证据，读元数据再读差异，最后读关键完整函数；控制输出比反复总结巨大文件更有效。
2. 把分支、源码提交、构建目录、APK SHA和测试输入一起记录。长任务恢复时先重新核对远端，保存旧成果，不静默丢弃也不把旧APK当最新。
3. 代理并行处理独立的规范/需求审阅，代码修改由主执行者集中；所有意见都能追溯到固定版本，避免审阅动态工作树时混淆原稿与已修代码。
4. 故障测试必须经过产品真实入口和持久化边界。DOM变化、mock返回成功、源码中出现某字符串都不能单独证明交付成功。
5. 在裁剪、压缩、分块和导出之后验证最终产物。全Vite目录通过不代表APK资源齐全，源码通过不代表发布包包含了修复。
6. 优先复用主线较完整实现，只移植兼容补丁，明确旧稿被替代的原因；保持数据schema向后兼容，持久字段不能随意删除。
7. 构建身份校验与运行验收分开记录；新备份格式也需要说明旧版本读取边界。没有本次设备证据就不宣称升级通过。
8. 私钥和口令放在临时私有目录，签名对比完成后清理；源码和证据包采用明确文件清单，排除秘密与依赖目录。
