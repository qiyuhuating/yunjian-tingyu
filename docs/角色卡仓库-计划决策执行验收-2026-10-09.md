# 可复用角色卡仓库：计划—决策—执行—验收

## 目标与计划

既有角色扮演草稿现已加入独立模板仓库。本轮保留其分类、备注、分页和卡库内AI拆分，并进一步验收和加固长期保存、手动新建、编辑、删除、复制、收藏、搜索和重复应用；继承最新 PR #3 的 AI 原文分类、原卡保留和世界书规则。接续基线 `f92404727e90c322a27af06bb45589770808fca9`，不回退到 main 或跳过前面的三份草稿。

验收要求：仅存卡不建聊天；同一卡能创建多个独立角色；修改和删除模板不改已有聊天；显式更新保留聊天、记忆、关系与 AI 连接；刷新和完整备份保留模板与头像；满库、过期编辑和跨窗口冲突不能产生部分更新。

## 决策

- 参考 [SillyTavern characters.js 固定提交](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/src/endpoints/characters.js) 的独立角色档案与导入、编辑、复制、导出、可选聊天删除设计。使用现有 React、Zod、Immer 和 IndexedDB 独立实现；没有复制或捆绑其 AGPL 源码，没有引入新的运行时依赖。
- 仓库保存人物模板、独立世界条目、原卡档案、标签和作者、收藏、修订与时间。模板没有 AI 连接、好感度、信任值、聊天、记忆和密钥槽。原卡内用户自己提供的文字字段仍原样保留，不宣称对任意导入文字中的秘密做自动清洗。
- 应用模板分配新的角色、消息和世界书编号；保留源索引及扩展以便往返导出。更新已有角色属于显式操作，不自动传播模板修改。
- 仓库与聊天角色使用不同容量：200 张模板，聊天角色仍最多 80 位；仓库 JSON 按 UTF-8 合计最多 12 MB。单卡世界书最多 1000 条，应用时检查聊天世界书的总容量。超限在同一 Immer/IndexedDB 提交流程中拒绝，模板导入与角色创建共同成功或共同失败。
- 相同语义 JSON 使用原卡规范化键序比较，不按文件名去重；不同卡片和同名卡保留，用户也可反复明确复制；50字姓名在复制时为后缀留出位置。PNG 头像沿用内容摘要去重，仓库和角色共用原文件引用。
- 修订检查拒绝旧模板的编辑、使用和删除。编辑草稿按已有卡编号或新卡分别存储，保留原有的已有卡修订校验。跨窗口落盘继续使用现有版本冲突保护。
- 复用现有设备状态持久化，不增加数据库版本。旧备份补空仓库，不自动把所有现有角色复制进仓库；已有角色由用户选择另存。新增字段不兼容旧客户端的严格 schema，不应直接回退客户端读取同一状态。

## 执行

1. `phone-model.ts` 定义模板专属 schema、唯一编号和归属、数量与总字节预算。
2. `lib/character-library.ts` 实现保存、去重、另存角色、编辑、删除、复制、导出与应用的纯状态操作，可用于真实 Immer 事务。
3. `app/character-library.tsx` 提供仓库列表与编辑器。支持人物与世界书基础字段、条目增删、收藏与搜索、选择开场白、应用到新角色或指定旧角色、下载当前卡与原卡。
4. `characters.tsx` 接入独立仓库入口；确认导入默认保存模板，可取消，另有「仅收入卡库」与「存为仓库角色卡」。AI 分析结果采用后保存相应模板，原卡档案独立保留。
5. `local-phone.ts` 的引用扫描、附件回收和旧资产迁移覆盖仓库与卡片编辑草稿。`local-backup.ts` 在恢复时同时重映射模板及嵌套草稿头像；多处引用同一头像只备份一份。
6. 本轮在已有仓库基础上补充 UTF-8 总预算、原卡键序规范化、过期应用与删除校验、重复复制与50字姓名后缀修复；卡片编辑草稿可保存超过 500 KB 的原卡档案，不沿用普通编辑器的截断上限；超出 12 MB 则提示精简。运行检查加入 GitHub Actions，文件索引和哈希清单同步更新。

## 验收与边界

具名结果保存于 `card-library-core-results.json`、`card-library-browser-results.json`、`card-library-regression-results.json` 和 `storage-regression-results.json`。

- 新仓库核心 19 项：旧状态、纯模板保存、去重、反复创建、设定隔离、显式更新、过期任务、复制、未知扩展、满库与原子拒绝、删除保护等。
- 新仓库真实页面 13 项：仅保存、刷新、搜索分类、反复使用、人物和高级世界书编辑及AI拆分、草稿恢复、收藏复制、实际 JSON 下载、更新角色、旧角色另存、删除、重复导入、手动世界条目、600 KB 档案草稿完整恢复。320 像素宽没有横向溢出。
- IndexedDB 与备份 13 项：5000 条历史、最小会话写入、跨窗口拒绝、内容去重、模板/草稿头像保留、ZIP 摘要与恢复重映射、原子失败、最后引用删除后的附件回收。
- 核心及媒体回归共 165 项（包含上述仓库核心），原角色扮演浏览器 10 项、现有媒体/路由/UI 浏览器 17 项通过。合计 218 项具名检查。
- 严格 TypeScript（包含无未使用变量/参数）、生产 Vite 构建和修改文件空白检查通过。生产构建仍有既有的 Three.js 大分块提示。

浏览器使用 Chromium 和真实渲染、IndexedDB、文件下载与 ZIP；模型测试使用本地 fixtures。新增仓库不需要发送模型请求，未使用真实付费模型、未新增 Android 原生逻辑或进行本轮 Android 真机测试。

仓库是当前设备本地保存，不是云端账号同步。JSON 导出包含人物、世界书和原扩展，不包含本机头像文件、聊天或 AI 配置；跨设备迁移使用完整 ZIP。完整备份清单现有 20 MB 上限仍适用，卡片与聊天都很大时需先分批导出或整理。世界书高级规则沿用 PR #3 的支持范围；卡片编辑器可编辑主次关键词、四种逻辑、整词与大小写、递归规则、扫描深度和插入位置，卡片世界书分页显示。

本轮提交为接续 PR #3 的叠加草稿；合并顺序仍为 #1 → #2 → #3 → 本草稿。既有签名 APK、随包资源和历史归档保持原版本，本轮没有签名、发布或宣称旧 APK 已有新功能。
