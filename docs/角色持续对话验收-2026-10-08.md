## 实际链路和并发

通过当前生产 React UI 发送消息、真实 SSE 透传、真实 IndexedDB 保存与刷新。真实 Key 仅在 Node 代理进程，浏览器储存的是无效代理占位值。三个隔离设备各承担部分角色，所有设备均导入完整 16 卡；双服务商第一次运行峰值六路网络请求，修复后 DeepSeek 峰值三路。单设备现有生成锁仍串行，不将本测试描述为 Hermes 群聊任务交接验收。

每卡固定 24 轮，包含情绪变化、反对意见、幽默、编程转日常、明确偏好更正、未发生的计划、访客资料、私人记号、身份核对，第 18 轮刷新。最后清空**用于模型请求的历史副本**，仅用持久化角色记忆和阶段摘要召回三项事实；数据库原文未删除。技术题为生成 Python 函数，没有把它描述成实际执行或编译测试。

## 已修复与剩余问题

应用为角色自己的 assistant 历史追加 sender 标签，模型会重复复制文件名，最严重单轮 11 个前缀。只去除**发送到模型的自身历史附加标签**，保留其他成员来源标签和原始消息。永久回归覆盖文字、Realtime 构造；16 卡同输入重跑的前缀计数全部为零。384 轮没有完全相同的整轮回复，没有每轮末尾追问；语义重复仍需人工判断。

历史首次运行存在一处实际保存的 cloudlet-messages 标签泄漏；修复后样本未再出现，不能据此声称所有协议格式问题永远消失。历史原文保持不变。

角色 v2 在身份核对时回答“我是你朋友，一个会记事的聊天对象”，没有保留清主人身份，记为**身份弱化**。其他 15 卡本次身份核对未发生角色/用户身份互换；这不是 15 卡所有人格维度的满分证明。部分角色原则趋向“答应的事算数”，但第 5 轮输入本来就在讨论兑现承诺，因此不能将趋同全部归因于提示词。现有提示词未作迎合自动评分的重写。

16 次自动评审采用隐藏版本的 A/B 标签、相同模型、完整原卡及相同用户输入。15 次逐字引用校验通过并偏好修复后；另一项轮号为字符串导致严格校验失败，原评审保留，不降低校验凑通过。评审把用户明确询问时的“我是清主人”错判为漂移，已撤销这一意见。正确记忆、角色自己的饮品及未来计划不直接计为缺陷。模型评审不等于独立人工盲测。

用户成年；原卡完整保留，本次测试使用非露骨日常/关系/技术输入。未对年龄不明确角色开展性内容场景，未宣称成人内容质量或所有领域均已验收。24 轮只提供本次样本证据，不代表数月记忆与人格稳定性。

## 缓存与预算

全部阶段已返回 usage **6,439,196 Token**；预留保守上界 **30,603,560**，授权上限 **100,000,000**。上限不是需要花完的目标。超时/拒绝且无 usage 的请求不认定为零账单。

| 服务商 | 生成尝试 | 可测缓存请求 | 输入 Token | 命中输入 Token | 最终加权命中率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| deepseek | 995 | 995 | 6164696 | 5189888 | 84.19% |
| openrouter | 42 | 26 | 149627 | 54976 | 36.74% |

另有两个无效 Key 负例，各返回 401。缓存率分母只含有缓存字段的请求输入 Token，不含输出 Token，不平均每轮百分比。DeepSeek 包含自动评审等不同工作负载，单列修复后角色对话 87.25%。缓存改善不建立延迟或修复因果关系。字段依据 [DeepSeek Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [OpenRouter Prompt Caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching)。

## 原始证据和备份

本地交付目录保留两阶段 results.json、dialogues.jsonl、request-usage.jsonl、角色原件 SHA-256 清单、各设备 checkpoint 和原始备份，另保留冷召回和逐项评审原文。完整私卡和原文不会加入应用仓库。

合并后的测试备份经当前源码 makeBackup/readBackup/stageBackup 再写入独立 IndexedDB 核验：**812 条消息、135 条记忆、12 份去重原件**。消息数/ID/文本、角色设定、记忆来源/修订和每张原件 SHA-256 一致；恢复时资产 UUID 合法重映射。该包是测试设备资料，恢复会替换目标设备状态，应先导出用户现有设备备份。

测试脚本：work/qa/live-cards.mjs；环境 LIVE_CARDS_DIR 指向原卡目录（含 source-index.json），LIVE_CARDS_RESULTS 指向私有结果目录，LIVE_CARDS_PROVIDERS 可限制 deepseek；进程注入 API Key，脚本检查 OpenRouter 目录零报价后才调用具体免费模型。每次预留量经 LIVE_PRIOR_RESERVED_UPPER_BOUND 带入，单次无自动重试；checkpoint 是证据快照，尚未提供自动续跑。本次未复用或恢复真实用户设备状态。

P1 Hermes 交接、真实生成媒体服务、长期人工对照和 Android 安装升级/原签名仍待后续阶段。PR 保持草稿，不发布新 APK。
